# 搁置与 Git Stash 分离实施方案

## 目标

在工作区左侧提供「提交」「搁置」「Git Stash」三个标签。用户从命令行创建 Stash 后，可以直接在「Git Stash」中找到它；通过「搁置所选改动」保存的补丁，可以直接在「搁置」中找到。

拆分前，提交面板只有「提交」和「搁置」两个标签。[ShelfCenter](../src/features/shelves/ui/ShelfCenter.tsx) 在搁置列表后渲染 [StashList](../src/features/shelves/ui/StashList.tsx)，且 Stash 为空时会隐藏整段。搁置是 GitCrest 数据库里的命名补丁，Git Stash 由 Git 保存在仓库的 `refs/stash`。拆分后的两个页面直接读取现有记录，无需迁移。

## 页面与交互

| 标签 | 内容 | 操作 |
| --- | --- | --- |
| 提交 | 工作区变更、暂存区和提交表单 | 暂存、取消暂存、提交、搁置所选改动 |
| 搁置 | GitCrest 的命名补丁及其变更范围 | 创建搁置、预览、应用、删除 |
| Git Stash | 原生 `stash@{n}` 条目及其文件 | 查看差异、应用、弹出、导入为搁置、删除 |

- 始终显示「Git Stash」标签。首次读取显示加载状态，读取成功但无条目时显示「此仓库暂无 Git Stash」，失败时显示错误和「重试」按钮。
- Stash 行继续显示现有名称、编号、来源分支、创建时间和未跟踪文件标记。展开后可从文件列表打开只读差异。编号用于显示，操作继续用 OID 标识条目，避免其他 Stash 的创建或删除改变编号后选错对象。
- 工具栏「搁置所选改动」、文件右键菜单、快捷键和分支切换前的搁置流程仍打开「搁置」，并传入相应文件或后续切换目标。
- 支持左右方向键循环切换三个标签，以及使用 Home、End 跳转。保持 `aria-selected`、`aria-controls`、面板标签和焦点一致。切换仓库时沿用当前回到「提交」的行为。
- GitCrest 自动创建的合并恢复备份仍出现在「Git Stash」，使用已有备份名称。Stash 的创建沿用命令行和现有自动备份流程。

## 操作与刷新规则

| 操作 | 数据结果 | 界面反馈与刷新 |
| --- | --- | --- |
| 应用 Stash | 应用到工作区，保留原条目 | 沿用后台任务和冲突处理。任务状态到达成功、失败或等待处理后，刷新当前仓库状态及 Stash 列表 |
| 弹出 Stash | 成功应用后移除原条目，发生冲突时保留原条目 | 同步任务状态与列表。冲突仍通过现有工作区和任务中心入口处理 |
| 删除 Stash | 用户确认后删除对应 OID 的条目 | 成功后刷新列表。失败时显示错误，并保留重试所需信息 |
| 导入为搁置 | 默认复制为一个搁置，保留 Stash | 停留在「Git Stash」，提示已导入并可在「搁置」查看。打开「搁置」时重新读取列表 |
| 导入并删除原条目 | 先保存搁置，再删除对应 Stash | 刷新 Stash 列表。若保存成功而删除失败，明确提示「搁置已保存，原 Stash 删除失败」 |

列表在进入标签时读取，并复用仓库的刷新信号。Stash 文件详情请求与列表请求都应在切换仓库或离开标签时取消或忽略过期响应。自动任务和外部命令可以改变仓库状态，从标签切换回来或使用现有刷新入口时应以当前 Git 数据为准。

## 实施步骤

### 1. 拆分标签和组件

- 在 [CommitPanel](../src/pages/workspace/CommitPanel.tsx) 把 `CommitPanelTab` 扩展为 `commit | shelves | stash`。用同一份标签定义生成标题、键盘导航顺序和面板关联，替换当前两个标签之间互切的逻辑。
- 从 `ShelfCenter` 移出 `StashList`。提交面板在选中 `stash` 时挂载独立面板，并传入当前仓库 ID、API 客户端、操作可用状态、刷新信号和差异查看回调。以仓库 ID 为组件 key，使选中条目、打开的文件和对话框随仓库切换重置。
- 将 Stash 任务提交回调接入 [ChangesView](../src/app/controllers/ChangesView.tsx) 的仓库状态和任务刷新逻辑。分支切换前搁置的后续动作继续由现有搁置回调处理。
- 在中英文资源中加入标签、空状态及导入反馈。复用工作区现有标签、加载、空状态和错误组件。

### 2. 处理独立列表与外部变更

- 区分初次读取、空列表、已有数据和加载失败。刷新时可继续显示已加载条目，读取失败时提示当前展示可能已过期。
- 继续使用 `onOpenFile(path, oid)` 打开只读差异。展开条目时保留对普通变更和未跟踪文件的读取。列表刷新发现已展开的 OID 消失时，清除其详情。
- 核对任务完成事件是否覆盖 Stash 弹出后的列表刷新。若当前历史刷新信号未覆盖，使用对应仓库的 Stash 任务状态触发重新读取。导入与删除可沿用列表自己的重读逻辑。

### 3. 完善导入的部分成功反馈

[导入处理](../crates/gitcrest-core/src/features/stash/ops_handlers.rs) 先保存搁置，再按用户选择删除原条目。保存成功后，响应同时包含已保存搁置和原条目的删除结果。

- 保存搁置失败时仍返回请求错误，保留原 Stash。保存成功后，接口返回搁置 ID、名称以及删除结果，即使随后删除失败。
- 保留现有 `dropped` 字段，增加可选的删除结果字段，例如 `dropStatus: notRequested | dropped | failed`。更新 [OpenAPI 定义](api/v1.yaml)、Rust DTO 和生成的 TypeScript 类型。客户端兼容仅返回 `dropped` 的旧响应。
- [StashActionDialog](../src/features/shelves/ui/StashActionDialog.tsx) 保持「导入后删除原条目」默认不勾选。保存成功后关闭导入对话框，在列表面板展示成功或部分成功反馈，随后重新读取 Stash。部分成功提示明确指出搁置已经存在，用户可以单独处理仍保留的原条目。

## 验收清单

- [x] 同一仓库同时有搁置和 Git Stash 时，两页分别只显示对应的记录；没有 Stash 时仍可进入「Git Stash」并看到空状态。
- [x] 从命令行创建 Stash 后，可以通过现有刷新入口或重新进入标签看到它。展开条目可以打开普通文件和未跟踪文件的差异。
- [x] 应用后原条目保留，弹出成功后条目消失，弹出发生冲突时条目保留。执行结果与 `git stash list` 一致。
- [x] 默认导入后原条目仍在，切到「搁置」可以看到新补丁。勾选删除时只删除选中的原条目。
- [x] 搁置保存成功、原 Stash 删除失败时，界面准确提示部分成功，重新进入两个页面可看到已保存的搁置和仍存在的原条目。
- [x] 用鼠标与键盘切换三个标签，焦点和选中态一致。切换仓库时不会出现上一个仓库的记录。
- [x] 工具栏、快捷键、文件右键以及分支切换前的搁置入口仍定位到正确仓库、文件和补丁范围。
- [x] 合并中断后保留下来的备份可在「Git Stash」中找到。
