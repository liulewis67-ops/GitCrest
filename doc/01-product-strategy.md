# GitCrest 产品策略

## 1. 愿景

GitCrest 希望让专业开发者在独立 Git 客户端中获得接近 IDE 级别的代码理解体验，同时保留桌面原生应用的速度、稳定性和跨平台可用性。

产品价值不是“替代 Git 命令行”，而是帮助开发者在复杂仓库、复杂分支和复杂变更中更快判断：发生了什么、是否安全、下一步该做什么。

## 2. 目标市场和首选细分

### 首选细分：专业开发者和大仓库维护者

用户任务：

- 在大型仓库中快速查看历史、分支和文件状态。
- 在提交前理解代码变更是否完整、是否危险。
- 在冲突、rebase、cherry-pick 等高风险操作中减少失误。

选择该细分的原因：

- 原始文档明确提出百万级提交、Monorepo、代码感知 Diff 和 Rust 原生性能。
- 该细分对性能、Diff 质量、快捷键和安全机制敏感，愿意为效率工具付费。
- 竞品中常见短板是 Electron 大仓卡顿、语义 Diff 不足、AI 支持浅。

### 第二细分：工程团队负责人

用户任务：

- 同时管理多个仓库和分支。
- 查看团队协作状态、远程状态和 PR/MR 上下文。
- 规范提交消息和工作流。

MVP 先满足个人高频工作流，二期再增强团队共享配置、PR/MR、CI/CD 和权限能力。

### 第三细分：开源贡献者和 DevOps 工程师

用户任务：

- 处理 fork、多个 remote、上游同步和 PR/MR。
- 快速定位构建失败对应的提交和变更。

该细分适合作为增长入口，但不是 MVP 首要交付对象。

## 3. 相对成本和定位

GitCrest 不以最低价取胜，而以高性能和高理解度取胜。定价应低于高端订阅工具，保留免费版吸引个人用户。

建议定位：

- 免费版：完整 P0 基础能力，限制云端 AI 次数。
- Pro：商业使用、无限 AI、优先支持和高级自动化。
- Team：共享工作流、团队策略、SSO、审计和协作视图。

## 4. 价值主张

### 对专业开发者

当前状态：Git 客户端能显示变更，但难以解释变更；大仓库中提交图和 Diff 容易卡顿。  
GitCrest 做法：使用 Electron + Rust sidecar（axum HTTP 服务）、Canvas 提交图、tree-sitter 语义 Diff 和 AI 摘要。  
改进后状态：用户能在同一个界面中快速理解历史、状态、Diff 和风险。

### 对团队负责人

当前状态：多个仓库、分支和远程状态分散，提交质量依赖个人习惯。  
GitCrest 做法：多仓库 Tab、分支收藏、Commit 模板、AI message 和后续团队配置。  
改进后状态：团队工作流更稳定，提交和分支管理更一致。

### 对 DevOps 和开源贡献者

当前状态：排查 CI、同步 fork 和管理 remote 需要在多个工具之间切换。  
GitCrest 做法：MVP 提供高性能 log、远程操作和多 remote；二期接入 CI 和 PR/MR。  
改进后状态：从提交到协作状态的链路更短。

## 5. 明确取舍

MVP 不做：

- 完整代码编辑器或 IDE 功能。
- 团队聊天、任务管理、项目管理。
- 深度 CI 配置编辑。
- 在线代码托管平台替代品。
- 复杂插件市场。

MVP 必须做深：

- 工作区、暂存、提交。
- 提交图和历史浏览。
- Diff、语义高亮和三路冲突。
- 分支、合并、rebase 和远程操作。
- 键盘优先和危险操作安全网。

## 6. 关键指标

北极星指标：每周完成关键 Git 工作流的活跃仓库数。

MVP 阶段 OMTM：用户从打开仓库到完成一次有效提交的成功率。

建议指标：

| 指标 | 目标 |
|---|---|
| 冷启动时间 | 低于 500ms |
| 100,000 提交仓库首屏提交图加载 | 低于 1s |
| 1,000 行文件 Diff 计算 | 低于 200ms |
| 核心工作流完成率 | 大于 90% |
| 提交消息 AI 接受率 | 大于 40% |
| 危险操作误执行率 | 持续下降 |

## 7. 增长策略

首选增长路径：产品驱动增长。

渠道：

- 开源仓库演示和性能 benchmark。
- 面向 Electron/Rust/前端工程师社区发布技术文章。
- 与 GitHub/GitLab 工作流结合，支持常用平台。
- 免费版降低试用成本，Pro 通过 AI 和商业授权变现。

## 8. 必备能力

必须自建：

- Git 操作核心和状态模型。
- 提交图布局与渲染。
- Diff 算法、语法解析、语义变更解释。
- 多窗口权限模型。
- 键盘和命令面板系统。

可集成：

- AI 云端模型。
- 本地 AI 模型运行时。
- GitHub/GitLab/Gitee API。
- 系统 Keychain 和签名能力。

## 9. 防御性

GitCrest 的防御来自组合能力：

- 原生性能和大仓库能力。
- 代码感知 Diff 的体验深度。
- 本地优先和凭证安全。
- 跨平台一致体验。
- 从个人工作流进入团队工作流的迁移成本。

## 10. 关键假设和验证实验

| 假设 | 风险 | 验证方式 |
|---|---|---|
| 专业开发者愿意使用独立 Git 客户端 | 市场已有 IDE/CLI 替代 | 发布可交互 Alpha，观察 7 日留存 |
| 语义 Diff 是强差异化 | 用户可能只需要普通 Diff | 对比普通 Diff 和语义 Diff 的任务完成时间 |
| Electron + Rust sidecar（axum HTTP 服务）能显著改善大仓体验 | 实现复杂度高 | 先做提交图和 Diff benchmark |
| AI Commit Message 有付费价值 | AI 输出可能不稳定 | 记录采纳率、编辑率和撤销率 |
| 免费版完整功能能带来增长 | 付费转化受影响 | 限制云端 AI、团队能力和商业授权 |
