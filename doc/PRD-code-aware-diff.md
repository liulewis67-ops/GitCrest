# GitCrest 代码感知 Diff 进阶设计

状态：设计已优化，第一版（结构导航、变更事实、按结构精确暂存）已实现，支持 10 种内置语言与外部语言插件，并通过单元、桌面 E2E 与真实应用验证。日期：2026-10-24。首要场景：日常提交审阅与精确暂存（用户已确认）。

本文承接 [MVP PRD](02-prd.md)、[UI/UX 规格](05-uiux-spec.md) 和 [Git 引擎架构](12-git-engine-architecture.md)。第 1 节说明相对上一版提案的优化，其余各节描述已实现的行为与约束。

## 1. 本版优化

上一版提案把一致性、隔离和预览都做成了新增基础设施：新的快照接口、写请求新字段、专用 Worker、单独的范围预览。逐项核对现有实现后发现，这些保证大多已经存在，或者可以用更小的代价取得。

| 上一版方案 | 优化后 | 理由 |
|---|---|---|
| 新增 `GET …/diff-review` 快照接口，返回源码、行映射与规范 Diff；`StagingPatchRequest` 增加 `reviewSnapshotId` | 复用现有两份文档：`context=full`（两侧完整文件）与 `context=hunks`（可暂存的 row）。前端逐行交叉校验两者，不一致即判定“陈旧”，并要求刷新 | 结构只决定“选择哪些已有 row”，从不生成 patch。写入的正确性仍由后端在取得写锁后核对 hunk 文档的 `revision` 保证（现有机制）。交叉校验覆盖两次读取之间的外部修改。无需改 API、OpenAPI、DTO 与权限 |
| 专用 Worker，执行 500ms 后终止 | 主线程异步解析：文本 Diff 先显示，结构随后补上；两侧合计上限 250,000 UTF-16 code units；最近 3 个文件的声明按 revision 缓存 | 实测热解析：125,000 字符的 TSX 单侧约 40ms，提取声明约 3ms（Node + 同一 WASM grammar）。分析是纯函数（`analyzeCodeReview`），实测超出预算时再迁入 Worker，迁移成本低 |
| 单独的“查看范围”预览步骤 | 原位预览：所选 row 在 Diff 中直接勾选并以左侧色条标出，底栏写明行数与涉及的结构 | 选中的就是将要提交给 Git 的内容，弹窗只会重复一遍；操作少一步，也与现有的按行暂存一致 |
| 在变更块视图里展开整段结构上下文 | 完整上下文在“完整文件”视图阅读；两个视图共用同一分析与结构 ID。完整文件视图中“选择以暂存…”会切到行视图并预选该结构 | 不需要第二套折叠与渲染逻辑。阅读与选择各用最合适的视图，切换时焦点随结构走 |
| 空行、注释的归属未定义 | 紧贴声明上方的注释、属性和装饰器归属该声明；某个变更块的其余行只属于一个结构时，块内的空行也归属它；其余归入“其它修改” | 新增函数时通常连带一个分隔空行。若空行不随结构走，按函数暂存后 index 会缺这一行 |

同时保留上一版中被验证为必要的约束：Git 的真实变更行是唯一的权威单位（一行可只取删除或新增一侧，见第 10.1 节 R1）；共用行不会整行随单个结构选入；审阅标记与选择相互独立；有语法错误的区域不生成描述，也不提供按结构选择。

## 2. 背景

现有阅读工具已有高亮、分栏/统一视图、Blame、完整文件对比和按行暂存，但开发者仍要自己把红绿文本还原成“哪个函数改了什么”。本功能把审阅单位扩展为函数、方法、类型、导入等结构，并把结构映射回 Git 已有的按行暂存。

代码感知是本地确定性分析，不依赖 AI 服务，不跟随 import 读取其它文件，不执行构建或宏。

## 3. 目标与验收

| 目标 | 验收方式 | 状态 |
|---|---|---|
| 快速定位 | 结构列表一次定位到指定函数，跨多个变更块的修改聚合为一项 | 已实现，有单元测试 |
| 理解结构变化 | 标签：新增、删除、参数、返回类型、函数体、声明、成员；每个标签可跳到证据所在行 | 已实现 |
| 精确选择 | 结构的可选修改与规范 Diff row 一一对应；暂存后未选内容原样保留 | 已实现，真实应用与 Git 验证 |
| 保持上下文 | 写入后在原位刷新；焦点结构仍有修改则保留，否则移到相邻结构 | 已实现，真实应用验证 |
| 不阻塞基本审阅 | 文本先显示；不支持、超限、解析失败或陈旧时说明原因，仍可按行操作 | 已实现 |
| 效率收益 | 用同一批样例对照旧界面，记录定位时间与暂存错误率 | 未测量；本文不虚构提升比例 |

## 4. 用户与场景

主用户是准备本地提交的开发者：一个文件里常同时有功能修改、调试代码、测试调整或格式变化，需要只提交其中一部分。

| 场景 | 行为 |
|---|---|
| 一个函数的修改分散在多个变更块 | 结构项聚合；“选择其修改”跨块选中全部 row |
| 同一变更块包含两个函数 | 两个结构各自只选自己的 row |
| 一个 row 同时修改两个结构 | 标为共用行；选择单个结构时只取属于它的一侧（删除行或新增行）；同一侧也被其它结构共有时排除并提示，用户可手动勾选 |
| 类声明与嵌套方法同时修改 | 类的“选择其修改”只选类自身的声明行；“连同成员一起选择”才包含方法 |
| 文件部分暂存 | 未暂存与已暂存分别分析；切换后旧选择清空，row 下标不混用 |
| 历史提交 | 同样的结构导航，只读，不出现选择与审阅标记 |

## 5. 交互

### 5.1 流程

1. 打开一个修改文件，先显示文本 Diff。
2. 分析完成后，左侧出现“本文件变更”结构栏，列出有变化的结构及其变更行数。
3. 单击结构只做定位：滚到它的第一处修改，并在代码中标出它的 row（行视图为左侧色条，完整文件视图为行号旁标记）。
4. 结构栏底部显示所选结构的路径（如 `UserClient › loadUser()`）、事实标签与变更行数；点击标签跳到证据行。
5. 行视图中点“选择其修改”，对应 row 被勾选，底栏显示“变更行 3 个，涉及 loadUser()”。用户可以继续增减任意行。
6. 点“暂存所选变更”。任务成功后 Diff 原位刷新，结构列表随之更新。

定位、选择、写入分为三步。单击结构从不触发选择或写操作。

### 5.2 布局

```text
文件列表 │ user-client.ts  未暂存
         ├────────────────────┬──────────────────────────────────
         │ 本文件变更  6 项 × │ 工具栏 … [结构] [完整文件] …
         │ 按名称筛选         ├────────────────┬─────────────────
         │ ● 导入 imports   1 │ 旧              │ 新
         │ ● 类 UserClient  7 │ ▌已选中的 row（色条 + 勾选）
         │   ● 方法 loadUser 3│                 │
         │   + 方法 clearCache│                 │
         │ ● 常量 TIMEOUT…  1 │                 │
         ├────────────────────┤                 │
         │ UserClient›loadUser│                 │
         │ [参数][返回类型][函数体]             │
         │ 变更行：3          │                 │
         │ [选择其修改][标为已审阅]             │
         ├────────────────────┴─────────────────┴─────────────────
         │ 3 项选择 · 变更行 3 个，涉及 loadUser()   [暂存所选变更]
```

结构栏与代码分别滚动，列表始终可见；工具栏“结构”按钮可收起，状态保存在 Diff 视图偏好中。Diff 区宽度小于 680px 时，结构栏浮在代码上方，不挤压代码。交互原型 [`prototype/code-aware-diff.html`](../prototype/code-aware-diff.html) 保留作设计参考，生产实现以本文为准。

### 5.3 键盘与可访问性

- 结构列表是 `tree`：方向键、Home/End 移动焦点，Enter/Space 定位；不占用 Monaco 与 F7/Shift+F7 的现有快捷键。
- 新增/删除/修改既用颜色，也有符号（+ − ●）和读屏标签；共用行有文字提示，不只依赖颜色。

### 5.4 审阅标记

“标为已审阅”只是本窗口内的提醒：不暂存，也不等同于 PR review。标记绑定结构自身变更行的指纹，这些行再有任何变化即失效。

## 6. 结构与变化

### 6.1 语言与识别的结构

内置 JavaScript/JSX、TypeScript/TSX、Rust、Python、Go、Java、C#、CSS、JSON 和 Markdown；其它语言通过[语言插件](language-plugins.md)接入。各语言识别的结构见该文档第 1 节。

| 方式 | 语言 | 说明 |
|---|---|---|
| 代码适配器 | JS/TS、Rust | 特殊形式多（`export`、箭头函数、getter/setter、`impl Trait for Type`），保留手写实现 |
| 声明式规则 | Python、Go、Java、C#、CSS、JSON | 规则是纯数据：节点类型 → 种类、名称来源、参数/返回类型/主体字段、包裹节点、导入。语法为 tree-sitter 官方 WebAssembly 版本 |
| 文本读取 | Markdown | 官方包没有 WebAssembly 版本；标题结构用逐行规则读取即可，跳过代码块与 front matter |
| 语言插件 | 任意 tree-sitter 语法 | 与内置声明式规则使用同一格式；插件文件夹提供清单与 `.wasm`，不执行代码 |

种类除函数、类等外，还有 `variable`、`rule`（CSS 规则、构建目标）、`section`（Markdown 章节）、`key`（JSON 键）。章节内的修改标为“内容”，JSON 键的修改标为“值”。

结构身份为“种类 + 名称路径”（如 `class:UserClient/method:loadUser`），两侧身份相同即为同一结构。同一容器内的重名声明（重载、多个 `impl S`）按出现次序编号，这类结构只报告变更行，不作新增、删除或签名判断。匿名回调不单独成项，归属其外层声明。

### 6.2 修改归属

- 每个变更 row 的旧行按旧文件结构、新行按新文件结构，分别归属到包含它的最内层声明；同一行上并列的两个声明都算所有者。
- 两侧所有者不同，或一行有多个所有者，即为共用行。
- 紧贴声明上方的注释、属性、装饰器属于该声明。空行若与某个结构处于同一变更块，且该块其余行只属于这一个结构，则归属该结构。
- 无法归属的顶层语句、空行与注释归入“其它修改”，不猜测所属函数。
- 容器的计数分为自身与成员两部分，同一 row 只计一次。

### 6.3 事实标签

| 标签 | 依据 | 不作出的结论 |
|---|---|---|
| 新增 / 删除 | 声明只存在于一侧 | 是否被调用、是否有遗漏 |
| 参数 | 参数列表文本（空白规整后）不同 | API 一定不兼容 |
| 返回类型 | 显式返回类型不同或增删 | 运行时返回值一定变化 |
| 函数体 | 函数体内有变更 row（与签名同一行时算签名） | 行为正确、测试已覆盖 |
| 声明 | 签名与函数体之外的变化：修饰符、注释、装饰器，或非函数声明本身 | — |
| 成员 | 容器内有嵌套结构发生变化 | — |

不默认隐藏“仅空白”修改：换行、注释位置和字符串中的空白都可能有意义。

## 7. 正确性

### 7.1 精确暂存规则

**权威单位是 hunk 文档中的变更 row。语法树只负责组织和解释，从不生成或改写 patch。**

1. 结构选择得到的是一组 `(hunkIndex, rowIndex)`，排序去重后与手动勾选合并，走现有的暂存、取消暂存与丢弃请求。
2. 共用行按侧归属：结构独占某一侧时只取该侧（删除行或新增行）；整行只在两侧的所有者都被选中时纳入，例如“连同成员一起选择”覆盖了父子两个结构。
3. 未暂存范围只能暂存，已暂存范围只能取消暂存；历史提交与独立 Diff 窗口没有写入口。不提供“按结构丢弃”，丢弃仍走现有的确认流程。
4. 选中一个函数不保证提交可以编译；不自动带上它依赖的 import 或其它文件。

### 7.2 一致性

- 行视图需要两份文档：hunk 文档（可暂存）与完整文件文档（解析用）。完整文件在 hunk 文档到达后读取，并随其 revision 变化重新读取。
- 分析前逐行核对：hunk 文档中每一行（含上下文行）的行号与文本必须与完整文件一致，且变更 row 一一对应。任何不一致都判为“陈旧”：不显示结构，提示刷新。
- 后端在写锁内核对 hunk 文档 revision；即使前端判断失误，也不会把与用户所见不同的内容写入 index。
- 异步结果按两份文档的 revision 作键，切换文件、范围或刷新后，旧结果不会渲染。

### 7.3 降级

| 情况 | 表现 |
|---|---|
| 无内置 grammar 的语言、二进制、symlink、子模块、冲突文件 | 不显示结构栏，沿用现有视图 |
| 超过 250,000 code units | 结构栏说明“文件过大”，文本 Diff 不受影响 |
| grammar 加载失败、完整文件读取失败 | 说明原因，文本 Diff 不受影响 |
| 两份文档不一致 | 提示“读取期间文件发生了变化”与“刷新”按钮 |
| 语法错误 | 照常列出受影响结构，但不给标签、不提供结构选择，并提示部分区域不可靠 |

### 8.1 实施中发现并修复的既有缺陷

真实应用验证暴露了三个与本功能无关、但直接破坏“精确暂存”的既有缺陷，已一并修复并补上回归测试：

| 缺陷 | 影响 | 修复 |
|---|---|---|
| 完整文件 Diff 使用 `--unified=2147483647`；Git 2.37 在该值下整数溢出，输出多个重叠的错误 hunk | 文件有多处修改时，“完整文件”视图显示错误内容，旧侧行号错位 | 改为 100,000,000 行上下文，覆盖 10MB 输出上限内的任何文件（[`git/diff.rs`](../crates/gitcrest-core/src/git/diff.rs)） |
| 按行暂存为每个 row 生成零上下文 hunk，位置取自工作区的绝对行号；`git apply` 对纯插入只按位置提示放置 | 上方有未选中的增删行时，暂存或取消暂存的插入行错位一行（例如 `if` 被放到 `return` 之后） | 正向位置按“旧侧 + 已选的前序 row”计算，反向位置按“新侧 − 已选的前序 row”计算，未选的行不再影响位置（[`diff/service.rs`](../crates/gitcrest-core/src/features/diff/service.rs)） |
| 按行暂存成功后不重新读取当前 Diff，读取时整个视图卸载 | 界面仍显示暂存前的内容，再次暂存会被判为陈旧；焦点与选择状态丢失 | 暂存类任务成功后重新读取；同一文件重新读取期间保留旧文档并禁用选择 |

另修复了本功能引入的一个问题：在完整文件视图中定位结构后切换视图，Monaco 会报 “TextModel got disposed before DiffEditorWidget model got reset”。现在卸载时先解除模型再释放。

## 10. 进阶路线（不含 AI）

本路线只包含本地、确定性的能力：结果可由源码、Git 与规则复核，不调用任何模型服务。现有的 AI 提交信息助手保持原样，不接入结构信息。

共同约束：

- 写入 index 的仍只有 Git 的真实变更行；新能力只改变“选哪些行”和“如何呈现”，不生成或改写 patch。
- 推断类结果（依赖提示、调试代码、格式化判断）一律以提示呈现，由用户确认，不自动修改选择。
- 每项能力都有降级：规则缺失或判断不确定时不显示，而不是显示猜测。

### 10.1 第一阶段：精确与安全（已实施）

R1–R8 均已实现，实施记录见本节末尾。

| 编号 | 能力 | 行为 | 关键实现 | 验收 |
|---|---|---|---|---|
| R1 | 半行暂存 | 删除行与新增行成对的 row，可只选其中一侧；行视图在两侧行号旁各有勾选框，整行勾选框在只选一侧时显示为部分选中。结构选择在共用行中只取属于本结构的一侧，共用行不再整体排除 | 选择项增加可选 `side: old/new`（暂存、取消暂存、丢弃、提交选择、搁置共用）；`select_rows` 只输出该侧的 patch 行，位置提示按第 7.1 节的正反向坐标计算；同一行不能同时整选又半选 | 替换函数 A 为 B 时可分别暂存“删除 A”与“新增 B”；暂存、取消暂存、丢弃半行后 index 与工作区逐行符合预期 |
| R2 | 重载身份 | 同一容器内同名声明（Java/C# 重载）按参数列表区分，如 `load(int)` 与 `load(String)`，恢复新增、删除与签名标签 | 收集声明后，对同名且参数文本互不相同的一组，以参数文本补充身份；子结构的路径随之更新。参数文本相同的仍按次序编号且不作判断 | 两个重载分别修改时各自独立显示与选择 |
| R3 | 细分声明变化 | 原“声明”标签细分为：修饰符（public、static、async、export 等增删）、注解/装饰器、注释；其余仍为“声明” | 比较声明头部（主体之前、参数与返回类型之外）的词法单元：差异全部属于修饰符词表、注解行或注释时给出对应标签 | 各语言样例中 `async`、`@Override`、文档注释变化给出准确标签 |
| R4 | 仅格式化 / 仅注释 | 结构的修改在去掉空白后词法单元完全相同时标“仅格式化”；去掉注释后相同时标“仅注释”，并可在列表中一键收起这类结构 | 按语言的注释语法剥离注释，字符串整体作为一个单元，比较两侧词法单元序列；字符串内的空白变化不算格式化 | 重新缩进、换行调整只得到“仅格式化”；字符串内容变化不会被误判 |
| R5 | 调试代码提示 | 新增的调试输出（`console.log`、`print(`、`dbg!`、`debugger`、`fmt.Println`、`System.out.println` 等）在行上标记，并汇总为“N 行调试代码”，可一键从选择中移除 | 每种语言提供调试模式列表，插件可在清单中声明；只检查新增一侧的变更行 | 选中含调试行的结构后，一键移除只取消这些行 |
| R6 | 同文件依赖提示 | 当已选的行使用了一个旧文件中不存在、且只由未选修改引入的名称（新增的 import、常量或函数）时，底栏提示“`sys` 来自未选择的修改”，可一键加入 | 名称取自词法单元；“引入者”为未选的导入行或新增结构的声明行；只在同一文件内判断，不做类型或跨文件解析 | 只选使用了新 import 的函数时出现提示，加入后提示消失 |
| R7 | 变更块结构标题 | 行视图每个变更块的标题显示它涉及的结构路径，替代 Git 按正则猜测的函数上下文 | 由分析结果中该块变更行的所有者得出 | 块标题与结构列表一致 |

验证中另发现并修复一个既有缺陷：打开的文件在保持选中时若状态变化（例如从未跟踪变为已修改），Diff 不会重新读取，界面会一直显示旧内容。现在 Diff 查询以该文件的状态条目为刷新键，状态变化即重新读取。仅内容变化而状态不变的外部编辑仍不会自动刷新，可用“重试”或切换文件刷新；写操作仍由 revision 校验保护。桌面 E2E 中对 Monaco 文本的读取改为轮询，避免在其异步排版完成前读取。
