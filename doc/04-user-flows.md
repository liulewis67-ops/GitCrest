# GitCrest 核心用户流程

## 1. 打开仓库

主流程：

1. 用户启动 GitCrest。
2. 欢迎页显示最近仓库。
3. 用户选择最近仓库或点击打开本地仓库。
4. 系统验证路径是否为 Git 仓库。
5. 主窗口加载仓库状态、当前分支、提交图和工作区。

异常：

- 路径不存在：提示重新选择。
- 不是 Git 仓库：提供初始化仓库入口。
- 权限不足：提示需要访问权限。
- 仓库过大：先显示骨架屏和首屏提交，后台继续加载。

成功标准：

- 用户能在 2 步内打开最近仓库。
- 打开后立即看到当前分支、工作区状态和提交图首屏。

## 2. 基础提交流程

主流程：

1. 用户修改文件。
2. 左侧 Changes 列表显示有 Git 状态的文件（M/A/D/?/!），按未暂存 / 已暂存分组。
3. 用户点击 Changes 中的文件，中央主区从提交图模式切换为 Diff 模式，以 IDEA-Split 左右分栏显示差异，右侧提交详情栏收起。
4. 用户在 Diff 中选择 hunk 或行进行暂存（也可在 Changes 中按文件级勾选）。
5. 用户手写 commit message，或按 `Cmd/Ctrl+G` 生成。
6. 用户编辑 message。
7. 用户按 `Cmd/Ctrl+Enter` 提交。
8. 提交成功后，工作区变干净；用户按 `Cmd/Ctrl+H`（或点击主区顶部「Graph」）回到提交图，看到新节点。

异常：

- 无暂存内容：提交按钮禁用，并提示需要先暂存。
- message 为空：提交按钮禁用。
- AI 失败：保留手写入口，不阻塞提交。
- Git hook 失败：显示 hook 输出，并提供重新提交。

成功标准：

- 用户不需要离开主窗口即可完成一次提交。
- AI 不自动提交，只作为可编辑建议。

## 3. 查看历史和定位提交

主流程：

1. 用户在提交图模式下滚动历史。
2. 点击提交节点。
3. 右侧展示提交信息、作者、时间和文件变更列表。
4. 用户点击文件列表中的某个文件，主区切换为 Diff 模式（来源 = 该提交对其父提交的差异），右侧详情栏暂时收起。
5. 用户在 Diff 中按 `F7` / `Shift+F7` 跳转下一个 / 上一个变更块。
6. 用户按 `Cmd/Ctrl+H`（或点击「Graph」）回到提交图，提交仍处于选中状态。
7. 用户可复制 SHA、打开独立 Diff 窗口、cherry-pick 等；或通过搜索按 SHA、作者、日期、message 定位。

异常：

- 搜索无结果：显示空状态和清除过滤入口。
- 大仓库加载中：显示后台任务和已加载范围。

成功标准：

- 搜索响应低于 200ms。
- 提交图滚动保持稳定帧率。

## 4. 分支切换

主流程：

1. 用户按 `Cmd/Ctrl+B` 打开分支切换器。
2. 输入分支名并选择目标分支。
3. 系统检查工作区是否干净。
4. 若干净，直接切换。
5. 若不干净，提供提交、Shelve、继续、取消。
6. 切换后刷新提交图、工作区和 ahead/behind。

异常：

- 切换失败：显示 Git 错误和建议操作。
- 目标分支不存在：提供创建分支。

成功标准：

- 非干净工作区不会被静默覆盖。
- 用户能理解切换前风险。

## 5. 处理冲突

主流程：

1. 用户执行 merge、pull 或 rebase。
2. 系统检测冲突文件。
3. 文件树用 Conflicted 颜色标记。
4. 用户打开冲突解决窗口。
5. 系统显示 ours/base/theirs 和结果区。
6. 用户逐块选择版本或手动编辑。
7. 可选：用户请求 AI 建议。
8. 用户标记 resolved。
9. 系统回到主窗口并更新状态。

异常：

- AI 建议不可用：不阻塞手动解决。
- 用户关闭窗口：保留当前未完成状态。
- 手动编辑结果仍有冲突标记：禁止标记 resolved。

成功标准：

- 用户能看到冲突来源和最终结果。
- 标记 resolved 前结果必须有效。

## 6. Shelve 场景切换

主流程：

1. 用户工作区有未提交变更。
2. 用户点击 Shelve 或按 `Cmd/Ctrl+Shift+S`。
3. 输入名称和描述。
4. 选择要搁置的文件或 hunk。
5. 系统生成 patch 并清理工作区对应变更。
6. 用户切换分支处理其他任务。
7. 用户从 Shelve 列表预览并应用。

异常：

- 应用 Shelve 产生冲突：进入冲突解决流程。
- Shelve patch 无效：提示失败原因并保留原条目。

成功标准：

- Shelve 不是黑盒 stash，恢复前必须可预览。
- 支持跨分支应用。

## 7. 交互式 Rebase

主流程：

1. 用户选中提交范围并启动 interactive rebase。
2. 系统创建备份引用。
3. 打开 rebase 编辑器。
4. 用户调整顺序和操作：pick、reword、edit、squash、fixup、drop。
5. 系统实时预览提交图变化。
6. 用户确认执行。
7. 执行完成后刷新提交图。

异常：

- 中途冲突：进入冲突解决流程。
- 用户取消：使用备份引用回滚。
- 操作会丢弃提交：需要明确确认。

成功标准：

- rebase 前必须可回滚。
- 用户在执行前能看到变更后的提交序列。

## 8. 远程同步

主流程：

1. 用户点击 fetch、pull 或 push。
2. 系统显示 remote、branch、ahead/behind。
3. 用户确认或直接执行。
4. 系统显示进度和结果。
5. 成功后刷新分支和提交图。

异常：

- 认证失败：打开凭证修复流程。
- push 被拒绝：显示原因和 fetch/pull 建议。
- force push：显示高风险确认和目标分支。

成功标准：

- 远程操作有可读日志。
- 高风险操作不会一键静默执行。
