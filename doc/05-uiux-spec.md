# GitCrest UI/UX 规格

## 1. 体验定位

GitCrest 的界面应像专业工程工具，而不是营销产品。整体风格应高密度、稳定、克制，适合用户连续工作数小时。

核心体验关键词：

- 快速：界面反馈即时，后台任务清晰。
- 清楚：Git 状态、分支、Diff 和风险一眼可见。
- 可控：危险操作有预览、撤销和明确后果。
- 专业：支持键盘、命令面板、多窗口和高信息密度。

## 2. 主窗口

### 2.1 标题栏

内容：

- 应用名称或当前仓库名称。
- 仓库 Tab。
- 新增 Tab 按钮。
- 全局搜索入口。
- 命令面板入口。
- 同步状态。
- 系统窗口控制。

行为：

- Tab 保存每个仓库的选中提交、滚动位置和工作区视图。
- 同步状态显示 fetch/pull/push 后台任务。
- 命令面板快捷键为 `Cmd/Ctrl+K`。

### 2.2 左侧栏

GitCrest 不在主导航中展示完整文件树。完整目录浏览属于 IDE 或文件管理器的职责；GitCrest 的左侧栏只显示与 Git 相关的对象。

分区：

- Changes（当前工作区变更）。
- 分支列表。
- Remotes。
- Shelve 列表。

Changes 区要求：

- 仅显示具有 Git 状态的文件：Modified、Added、Deleted、Renamed、Untracked、Conflicted。干净文件不出现。
- 分组：未暂存、已暂存。冲突文件置顶且使用 Conflicted 色。
- 每行：状态徽标（M/A/D/R/?/!）+ 路径（按状态色着色）+ `+adds -dels` 增删行数。
- 支持按状态过滤和路径模糊搜索。
- 复选框用于文件级暂存；右键菜单提供 hunk 暂存、放弃变更、忽略、复制路径、在 IDE 中打开。
- 点击文件触发主区域进入 Diff 模式（见 2.3）。
- 文件数较多时使用虚拟滚动。

分支列表要求：

- 显示当前分支。
- 显示 ahead/behind。
- 收藏分支置顶。
- 远程分支视觉弱于本地分支。

### 2.3 中央主区（双模式）

中央主区在两种模式之间切换：

| 模式 | 进入方式 | 内容 |
|---|---|---|
| 提交图 | 默认；点击工具栏「提交图」；快捷键 `Cmd/Ctrl+H` | 提交节点、分支线、ref 徽标 |
| Diff | 点击 Changes 中的文件；点击提交详情中的文件；快捷键 `Cmd/Ctrl+D` | 单个文件的代码感知 Diff |

切换原则：

- 模式互斥：进入 Diff 模式时提交图隐藏，进入提交图模式时 Diff 关闭。两种模式都可随时打开，互不丢失最近选择。
- 工具栏的模式切换按钮始终常驻在主区顶部，显示当前模式和回到另一模式的入口。
- 同一仓库 Tab 切回时恢复上次模式和选中对象。

#### 2.3.1 提交图模式

内容：

- 提交节点和分支线。
- 提交标题。
- 作者。
- 相对时间。
- 标签和分支徽标。

交互：

- 点击节点选中提交。
- 双击切换到提交详情。
- 右键打开提交菜单。
- 搜索结果高亮。
- 支持虚拟滚动。

视觉：

- 分支线颜色应稳定且可区分。
- 当前 HEAD 节点更醒目。
- 选中提交使用明显背景和左侧指示线。

#### 2.3.2 Diff 模式

GitCrest 主区的 Diff 采用 JetBrains IDE 同款 **左右分栏（Split）** 为默认且唯一主样式，与 Unified 视图仅在独立 Diff 窗口中提供切换。

布局：

- 顶部工具栏：当前文件路径、上一/下一变更块、忽略空白、显示空白字符、Split/Unified、Blame、「打开提交图」回到提交图模式。
- 主体：左侧 Old、右侧 New 两个等宽编辑器面板，行号在各自外侧。
- 两栏之间一条 12-16px 中央通道（Connector）用于绘制对应变更块的连接条：新增显示绿色梯形，删除显示红色梯形，修改显示黄色梯形。Connector 让用户一眼看出两侧的对齐关系。
- 上下文未修改行可折叠为「N 行未修改」摘要带。
- 同步滚动：左右滚动联动；锚定到当前焦点变更。
- 当 Diff 来源是工作区（Changes 点击），顶部出现 Stage hunk / Stage line / Discard 操作；当来源是某个提交（提交详情点击文件），这些写操作禁用。

来源标识：

- 工作区 Diff：标题显示「未提交变更 · path」并以 Working Tree 色徽标标识。
- 提交 Diff：标题显示提交主题和 SHA 短哈希。

### 2.4 右侧详情区

右侧详情区只在提交图模式下显示，承担「当前选中提交的元信息和文件列表」。Diff 模式下右侧详情区收起，让 Split Diff 获得最大水平空间。

模式：

- 提交详情。
- 变更摘要。
- Blame 信息（在 Diff 模式中以工具栏 toggle 显示，不占用右侧）。

提交详情内容：

- SHA、作者、提交时间。
- message 标题和正文。
- 父提交和子提交。
- 文件变更列表。点击文件即进入 Diff 模式查看该提交对该文件的修改。
- 操作按钮：复制 SHA、cherry-pick、tag、在新窗口中打开 Diff。

### 2.5 底部工作区

分区：

- 未暂存。
- 已暂存。
- Commit 表单。

工作区行为：

- 拖拽文件到已暂存区等同暂存。
- 点击文件显示 Diff。
- hunk 和行级暂存在 Diff 内完成。
- 提交按钮仅在有暂存内容且 message 有效时启用。

Commit 表单：

- 标题输入。
- 正文折叠区。
- 模板选择。
- AI message 按钮。
- 提交按钮。
- amend 选项。

## 3. Diff（中央 Diff 模式 和 独立 Diff 窗口）

### 3.1 通用 Diff 行规则

- 新增使用绿色背景，删除使用红色背景。
- 修改内容用 token 级高亮（基于 tree-sitter）。
- 未修改上下文可折叠为「N 行未修改」带。
- 语义块边界（函数、类、模块）在 Diff 左侧 gutter 显示名称。

### 3.2 Split 模式（默认）

- 左侧 old，右侧 new，两栏等宽。
- 行号在各自外侧，便于光标停留时读取「在哪一侧的哪一行」。
- 空行占位保持行高一致，使对应变更横向对齐。
- 中央通道绘制连接条：新增绿、删除红、修改黄。
- 同步滚动；上一/下一变更块快捷键 `F7` / `Shift+F7`。

### 3.3 Unified 模式（仅独立 Diff 窗口提供切换）

- 主区不提供 Unified 切换，避免主工作流出现两套滚动行为。
- 在独立 Diff 窗口中可切换：单列展示，行前标记 `+`、`-`、空格。

### 3.4 独立 Diff 窗口（多文件 / 离开主窗口对比）

布局：

- 顶部：文件 Tab、Split/Unified 切换、Blame、搜索。
- 左侧：文件列表。
- 主区域：Diff（默认 Split）。
- 底部：行数统计、编码、语言、AI 摘要状态。

## 4. 冲突解决窗口

布局：

- 顶部：冲突文件列表和进度。
- 主区域：ours、base、theirs 三列。
- 底部：结果预览。
- 右侧：AI 建议和操作历史。

操作：

- 接受 ours。
- 接受 theirs。
- 手动编辑。
- 逐块合并。
- 标记 resolved。
- 回到主窗口。

安全：

- 结果中仍有冲突标记时，禁用 resolved。
- 关闭窗口不丢弃用户手动编辑，除非用户明确放弃。

## 5. 设置窗口

分区：

- General：启动、最近仓库、默认路径。
- Appearance：主题、字体大小、紧凑模式。
- Shortcuts：快捷键编辑和冲突检测。
- Git：默认 merge/rebase 策略、签名、hooks。
- AI：provider、本地/云端、隐私范围。
- Credentials：SSH、HTTPS token。
- Updates：自动更新、渠道、签名状态。
- Security：危险操作确认策略。

## 6. 空状态

| 场景 | 文案方向 | 主操作 |
|---|---|---|
| 无最近仓库 | 打开或克隆一个仓库开始 | 打开仓库、克隆 |
| 工作区干净 | 当前没有未提交变更 | 查看历史 |
| 搜索无结果 | 没有匹配的提交或文件 | 清除搜索 |
| 无远程 | 当前仓库没有 remote | 添加 remote |
| AI 未配置 | 配置 AI 后可生成建议 | 打开 AI 设置 |

## 7. 响应式和可调整布局

桌面应用优先支持 1280px 以上宽度。低宽度时：

- 左侧栏可折叠。
- 右侧详情区可变为底部抽屉。
- 底部工作区可最大化。
- Diff 窗口保留 Split/Unified，但默认切到 Unified。

所有栏宽可拖拽调整，并保存到仓库级布局状态。
