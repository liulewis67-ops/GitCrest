# 受保护的操作（实验）

受保护的操作把“切换分支、检出提交、拉取”这几个会动工作区的 Git 动作，变成**分步、可中断后继续**的持久操作：本地修改会先被安全保存，每一步都需要你确认，应用关闭或重启后操作仍在，可以接着做或中止。**默认关闭**，不开启时一切照旧。

## 怎么开启

需要两处都打开：

1. **核心端**：用环境变量 `GITCREST_OPERATION_CREATION=1` 启动核心（`1`/`true` 开，`0`/`false` 关）。没开时，创建操作的接口返回 403 `OPERATION_CREATION_DISABLED`，应用会自动回到原有流程。已存在的操作不受这个开关影响，仍可查询和继续。
2. **应用端**：设置页里“受保护的操作（实验）”，勾选“使用受保护的操作”。这个选项只存在本机，勾选前后互不影响其他设备。

两处缺一，行为都和原来一样；核心比较旧、没有这套接口时同样自动回退。

## 哪些入口会用到

| 入口 | 走分步操作的条件 |
|---|---|
| 分支切换器：切换到本地分支 | 有会被覆盖的本地修改，或你选择“保留在当前分支” |
| 分支切换器：检出提交（分离 HEAD）、命令面板“检出所选提交” | 同上 |
| 拉取对话框：合并 / 变基 | 开启后总是 |

不走分步操作的情况：切换到远端分支（要先创建本地分支，这套接口不做）、没有会被覆盖的本地修改的普通切换。

## 你会看到什么

启动后会自动打开**任务中心**，里面的“需要处理的操作”面板显示当前状态和可做的选择。以拉取为例：

1. “等待你的选择”：**查看已拉取的更改**，或取消。
2. 选择**变基到上游**（或快进、合并，视情况而定）。
3. 没有冲突就自动完成，面板消失。
4. 有冲突时显示“等待你的处理（历史冲突）”和“请在工作区中解决冲突”，解决并暂存后点**继续变基**；想放弃点**中止变基**，仓库回到开始之前。

面板里还会显示：为什么停下（与任务中心同样的白话说明）、仍被保留的本地修改副本数。恢复一个保存的修改时若产生冲突，按提示解决后点“我已解决冲突”。

标题栏的**任务按钮**在当前仓库有等待你的操作时会出现一个琥珀色圆点（读屏器会读“等待你处理的操作：N”），即使应用刚重启、没有任何任务在运行。目前只统计当前选中的仓库。

## 它保护了什么

- 保存本地修改的副本在操作结束前一直保留，面板上能看到数量。
- 每一步先复核仓库状态（分支、提交、修改内容）再动手，状态变了就停下并说明，而不是硬做。
- 同一个仓库同一时间只有一个写入类操作；外部工具（编辑器、终端）短暂占着 Git 的索引锁时，写索引的命令最多等 2 秒。
- 重复提交同一个请求不会执行两次（幂等）。

## 怎么退出

- 取消勾选设置里的选项即可，之后的切换、检出、拉取回到原流程；已经在进行的操作仍然可以在任务中心里继续或中止。
- 核心端把 `GITCREST_OPERATION_CREATION` 关掉，同样只影响“新建”，不影响已有操作。

## 已知限制

- 只在 Windows 上验证过；macOS/Linux 的测试工作流（`.github/workflows/cross-platform.yml`）已写好但尚未实际运行。
- 面板只统计和显示当前仓库的操作；没有系统通知。
- 升级数据库时会在同目录留一份升级前备份，不会自动清理，恢复办法见 [升级失败后的数据库恢复](database-upgrade-recovery.md)。
- 默认是否开启、分步流程是否取代原来的一步流程，是尚未做出的产品决定。
