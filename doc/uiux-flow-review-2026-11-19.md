# GitCrest 操作流与 UI/UX 复评

日期：2026-11-19。目标：让状态和操作表达下一步，减少常驻教程；保持现有桌面 Git 工作台风格。

## 方法与覆盖

两份隔离评审：A 检查任务路径和信息层级；B 检查源码、截图及机械扫描。A 完成后才合并 B 的扫描结果。基线和改后界面均使用独立 Electron 配置、数据库及临时 Git 仓库，未使用真实仓库执行操作。

覆盖欢迎页、克隆、变更树、提交、AI 建议、分支切换、历史、Pull/Push、任务与冲突恢复、设置及 Hook。视觉证据位于 `.review/flow-before` 与 `.review/flow-after`；这些是本地验证产物。旧 S0.4 截图不作为当前界面的证据。

## 评审结论

界面的主要问题是信息层级和操作衔接：禁用原因藏在 tooltip；高级选项与基础配置争夺首屏；教程和文件清单把主要动作推到屏下。现有文件状态、差异视图和冲突解决流程符合 Git 工作台的特点，无需替换视觉语言。

基线启发式评价（每项 0–4，主观评审，不是用户实验）：

| 项目 | 分数 | 依据 |
|---|---:|---|
| 状态可见 | 2 | 有任务状态，提交前置缺口主要靠 title |
| 符合用户语言 | 3 | 分支/文件/暂存概念明确，帮助混入实现细节 |
| 用户控制 | 3 | 支持取消、回退与确认，缺少部分焦点交接 |
| 一致性 | 3 | 共享菜单和对话框，部分次级动作同权重 |
| 错误预防 | 3 | Git preflight、危险操作确认和隐私同意保留 |
| 识别优于记忆 | 2 | 用户要记住说明、猜测禁用按钮的下一步 |
| 效率 | 3 | 快捷键/菜单完善，配置表单过长 |
| 精简 | 2 | 同屏出现多段说明和重复教程 |
| 错误恢复 | 3 | 重试、诊断详情和冲突恢复入口已有基础 |
| 帮助 | 2 | 帮助可得，但常驻而且偏长 |
| 合计 | 26/40 | 以减少阅读负担和改善操作衔接为本次重点 |

保留的优点：文件状态与内容直接关联；错误原始诊断已有折叠入口；冲突解决已采用“选择→检查→保存→继续”的状态式流程。

## 优先问题与落地

| 优先级 | 问题 | 已实施 |
|---|---|---|
| P1 | 提交前不知道该做什么 | 由状态选择就近操作：暂存全部、填写提交说明、解决冲突；后台任务期间隐藏不可执行的下一步。无自动暂存或自动提交 |
| P1 | 提交区常驻额外说明框和重复操作 | 补充说明按需展开；已有正文自动可见；Enter 从摘要交接到正文；次级提交方式保留在原动作菜单 |
| P1 | Hook 基础配置与高级配置混排 | 基础字段优先；合并/冲突选项与命令分组折叠；非默认策略及已有命令仍可发现；语法帮助就近展开 |
| P1 | 添加/编辑 Hook 后表单和结果在屏外 | 新表单滚动到视野并聚焦名称；目标添加后返回选择器；保存回到对应规则，取消回到入口；操作栏保持可到达 |
| P2 | Push/Pull 文件清单挤压动作 | 文件清单折叠为计数；提交预览保留；Push 的标签选项按需展开；落后时突出获取检查；已同步的 Push 有明确完成出口 |
| P2 | 获取分支为空时只有说明 | 推送目标选择增加真实 Fetch 操作，等待已有任务/分支刷新链路更新选项 |
| P2 | AI 生成按钮被 prompt 与所有 diff 推远 | 服务商、模型、范围、数据量和明确同意常驻；prompt/逐文件内容按需查看；无默认同意或自动发送 |
| P2 | 任务恢复动作缺少主次 | 有冲突时突出解决；preflight 允许继续时突出继续；刷新/中止仍保留，危险确认不变 |
| P3 | 通用设置、欢迎页与首次使用教程重复解释 | 常识性重复段落移除；专业说明收进 HelpDisclosure；键盘说明保留给辅助技术；首次提示默认只显示短入口 |
| P3 | 条件区域生硬出现 | 对话框与新增状态轻量淡入，配合焦点交接；不用布局动画或全局 transition；尊重系统与应用减少动态效果设置 |

提交逻辑补充：暂存 HTTP 请求及暂存任务仍在进行时不启用 Commit；Push 刷新 preflight 时，旧预览不能用于执行普通或强制推送。

## 按使用方式检查

- 首次使用：不再必须阅读教程才能找到暂存或提交说明入口。
- 键盘操作：摘要到正文、Hook 名称初始焦点、添加目标后的焦点、保存/取消返回位置均有明确交接。
- 熟练使用：快捷键、原提交动作菜单、搜索下拉、已有自定义 Hook 策略仍可用。

未改动历史浏览的结构、Git 操作语义和冲突编辑器生命周期。强推的 ref/OID 与覆盖范围、中止确认、AI 发送对象和明确同意仍在决策位置展示。

## 扫描与验证

机械扫描最初仅报告四处既有 side-tab 警告；它们是 Diff 行号几何边界和代码结构焦点标记，不是本次问题，未为了通过扫描而删除功能标记。

验证结果：147 个测试文件、906 项前端测试通过；两套 TypeScript 检查、完整构建和前端依赖边界通过。新增测试检查下一步不会自动执行、焦点交接、高级配置保留、缺分支可获取、刷新期间不能推送。实际 Electron 窗口验证摘要聚焦、Commit 启用、Hook 保存/取消的焦点返回、菜单、中文深色最小窗口布局与减少动态效果（动画时长为 0.01ms）。
