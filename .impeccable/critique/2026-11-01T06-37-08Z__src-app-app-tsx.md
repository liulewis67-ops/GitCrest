## Design specificity

GitCrest feels authored for deliberate Git work. The composition is a workbench rather than a generic dashboard: staged-file composition, branch orientation, HEAD markers, graph topology and comparison labels carry the character. Neutral surfaces leave the code and semantic changes in charge. The welcome surface prioritizes returning to a checkout; duplicate basename labels and path/branch filtering address a real developer problem. Shared SVG controls belong to the same visual language. Both built-in themes retain the same hierarchy. No generic marketing ornament or unrelated visual metaphor is needed here.

## What's working

1. **Returning to work is direct.** Populated Welcome leads with recent repositories; open/clone/initialize share one action row. Fresh 960×700 imagery shows identical checkout names distinguished by parent labels. Live `main` filtering, Down to a row and Right to Favorite worked, with one normal Tab stop per row.
2. **High-stakes review has a legible sequence.** Target → mode → immediate consequence → optional comparison → impact → acknowledgement → final action. Recovery is secondary and collapsed. The footer stays visible at the narrow review size. Actual hard-reset preflight refused local changes; no mutation was executed.
3. **The visual system supports Git reasoning.** HEAD, status letters, labels and graph topology avoid dependence on color alone. Fresh light/dark History and Workspace captures retain readable primary content, modest dividers and stable action hierarchy. The narrow structure hint stays within its rail and no longer covers the code header.

## Priority refinements

Only three minor, evidenced priorities emerged; none warrants an invented larger defect.

### [P3] The narrow structure header truncates its useful summary

At CSS 960×700 the in-flow rail displays “Changes in this file” followed by a clipped “Struct…” instead of the structures/rows summary. The review progress below is readable and the panel remains functional, but the top-level quantity cue becomes visual debris precisely where space is tight. Give the count a second line or show a compact count beneath the title; keep the close action fixed. Suggested command: `$impeccable adapt`.

Evidence: `.review/d4-final-a-structure.png`, `StructureOutline.tsx` header. Side-by-side code is necessarily narrow with the rail open; unified/focus/hide controls already provide good escape paths, so that tradeoff is not independently scored as a blocker.

### [P3] Reset's blocked explanation remains broader than its known cause

The live hard-reset preview correctly states that ten local changed paths block the operation, then adds “The target may already be HEAD, a Git operation may be active, or hard reset may overwrite local changes.” That second sentence reopens a diagnosis already settled by the facts. Prefer the specific known blocker, retaining a generic fallback when the preview does not identify one. Display a friendly branch name in the main instruction, with full ref/SHA available as supporting detail. Suggested command: `$impeccable clarify`.

Evidence: `.review/d4-final-a-reset-impact.png`, `ResetDialog.tsx` and workflow strings. Prevention itself worked; this is precision of explanation, not unsafe behavior.

### [P3] Name the action represented by each help shortcut

The “Switch branches and review history” topic discusses History, switching, worktrees and Reset, then displays only `Ctrl+B`. The recovery topic discusses Tasks, missing repositories and reset backups, then displays only `Ctrl+K`. Experienced users can infer these are branch switcher and palette shortcuts; a first-timer can reasonably apply the badge to the topic's other task. Render “Open branch switcher · Ctrl+B” and “Open command palette · Ctrl+K”, using the same current binding source. Suggested command: `$impeccable document`.

Evidence: live Help search for `reset` returned both topics; source maps them to `branchSwitcher` and `commandPalette`.

## Emotional journey

Welcome starts with confidence: explicit repository identity and private-on-device reassurance. Workspace is a concentrated technical environment, but selection, staged counts and immediate code comparison anchor the next action. The emotional valley is Reset: removing commits and replacing tracked files require concentration. Plain consequences, actual impact, disabled unsafe submission and a persistent Cancel button provide credible reassurance. The closing experience is controlled: Help dismisses to its opener, and recovery promises are bounded. Final success/remote-operation outcomes were not executed, so this review does not claim their emotional ending was live validated.
